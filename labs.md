## MIT 6.5840

[mit-6.5840-labs](https://github.com/lvdousha26/mit-6.5840-labs), Go

MapReduce, Raft (election, replication, persistence) and a linearizable KV store, written from the paper and the handouts rather than the official skeleton — the course asks students not to publish solutions, so this is a separate implementation. Three pieces worth reading: each MapReduce task carries a version that increments on reassignment, so a late report from a presumed-dead worker cannot slip its intermediate files into the reduce inputs; Raft commits only by counting replicas of a current-term entry (Figure 8) and appends a no-op on winning an election, otherwise inherited entries sit uncommitted; KV routes `Get` through the log and dedupes on `(clientID, seqNo)`. `labrpc` is a channel-based network that can drop a reply after the handler ran or restart a server without clients noticing. Sharded KV (Lab 4) is not included.

## tiny-autograd

[tiny-autograd](https://github.com/lvdousha26/tiny-autograd), C++17

An autograd engine written from scratch. A `Tensor` records the op that produced it and which nodes consumed it; `graph::backward_tree` walks the ops backwards with an explicit stack, and `graph::backward_memo` does a memoized DFS that also gets DAGs right. Ops go from matmul, transpose and softmax through GELU, SiLU, layer norm and top-k; FC and conv layers are built on top, with MNIST training, GEMM and Transformer-block demos, and a small C ABI that the repo below calls from Python.

## tiny-sparse-autoencoder

[tiny-sparse-autoencoder](https://github.com/lvdousha26/tiny-sparse-autoencoder), Python

A sparse autoencoder whose forward and backward passes run inside tiny-autograd, no PyTorch involved. Two backends share one API: the engine one (top-k or ReLU+L1, linear decoder, MSE) and an independent NumPy reference with hand-derived gradients and Adam, kept so the engine's gradients can be checked line by line. The benchmark uses a known ground-truth dictionary, so whether the features are real is a number rather than a guess.

## data-preparation-pipeline

[data-preparation-pipeline](https://github.com/lvdousha26/data-preparation-pipeline), Python

A runnable LLM pretraining data pipeline, following the CS246 guest lecture on data preparation: 12 stages from raw web pages to packed token sequences — extract, dedup at url/doc/line level, LangID, heuristic filters, decontamination, quality distillation, mixing, tokenizer, best-fit plus FIM packing, stage schedule. Each stage reads the previous `docs.jsonl` and writes its own directory with a `stats.json`, so any stage can be rerun, diffed, or ablated on its own.

## socket-lab

[socket-lab](https://github.com/lvdousha26/socket-lab), C

Unix sockets in the order the problems appear: a one-client echo server, then fork/thread/select versions, then a 4-byte big-endian length prefix so a receiver can tell two messages apart. The concurrent section is mostly about what breaks — `accept()` interrupted by `SIGCHLD`, a heap-allocated per-thread argument instead of `&cfd`, `fd_set` rebuilt on every `select()` call. The frame client has a `-B` flag that writes several frames before reading any reply, which is the case that makes a naive echo loop visibly wrong. A length read off the wire is checked against both the cap and the caller's buffer before anything is allocated.

## tiny-rpc

[tiny-rpc](https://github.com/lvdousha26/tiny-rpc), C

What sits between `send()` and a function call: a 16-byte fixed header (magic, request id, method id, body length), an argument codec that follows IDL order, stubs generated by a small Python script, and a dispatcher. The server is an accept loop feeding a bounded queue worked by a fixed thread pool; a full queue closes the new connection instead of blocking the accept loop. One worker owns a connection for its whole lifetime, so no per-fd write lock is needed. `rpc_pipeline` sends six requests before reading and matches replies by request id, though the workers still answer in order.

## minigit

[minigit](https://github.com/lvdousha26/minigit), Go

A small Git that writes a `.git` directory real Git can read: `git log`, `git status`, `git cat-file`, `git ls-tree` and `git fsck --strict` all run against it in the tests, and it reads Git-created objects and the index the other way. Covers loose objects (SHA-1 over `<type> <len>\0<content>`, zlib), the DIRC v2 index with its 8-byte alignment and trailing checksum, tree entries, commits and refs. Tree sorting is the easy one to get wrong — a directory name compares as if it had a trailing `/`, so `a-b.txt`, `a.txt`, `a/` is not plain string order and `git fsck --strict` rejects it. No packfiles, merges, checkout, remotes or reflog.
